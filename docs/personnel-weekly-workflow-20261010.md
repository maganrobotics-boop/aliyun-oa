# 周报、周会与个人主页

本次按用户要求接续阿里云 OA：自动生成本人工作确认单 → 本人核对工作量 → 石永亮或冯永玄任一人审核 → 自动进入个人主页的已审核记录。

## 行为

- 新的 AI `weekly_report` / `meeting_minutes` 任务成功保存时，数据库同一事务生成提交者的 OA 工作确认单。失败、取消和普通文档不生成。现有待办会自动列出本人待确认数量。
- 资料库新提交的周报、周会（标题或分类明确标记）也自动生成提交者的工作确认单。触发点是完整投稿事件：常规正文及分段正文全部保存后才建单，不依赖更新当前版本指针。既有历史文档不批量追溯。
- 资料库上传预览可选择“个人周报”或“集体周会”，无需修改文件名。提交成功后及“我的资料”中的周报/周会卡片都有“分发给周会参与成员”入口。仅原提交账号能分发；每份资料最多关联 50 个实名、有效 NDA 账号，可补选、查看已分发人员并安全重试。
- 资料库分发使用首次工作确认单的正文快照；重复分发不新增记录、不覆盖本人已填写或已确认的内容。原资料修订后会提示继续沿用已有快照，新一轮周会需上传新资料。历史资料可由本人明确发起分发后建单，不会批量回填。
- 集体周会在 AI 工作台的成果下关联参与成员，使用已登记成员 ID；每人收到独立确认单，须填写本人的实际工作。不会按 AI 提及姓名猜测身份，也不会把整份集体成果自动算给每个人。关联成员可以阅读这份总结。
- 本人核对文本工作量并提交后，自动调用现有原生 OA 审批，保留原审批 PDF、不可变修订、退回重提与审计机制。初始确认单是 OA 待办，正式审批编号在本人确认后生成。
- 新周报采用 `weeklyReviewVersion: 2`，只有当前配置中的任一独立技术审核人可以通过，不再增加负责人终审。技术成果审批及财务、采购路线不变。审核人继续绑定现有 `oa_review_policy` 中的实名账号，不通过显示姓名授予权限。
- 已归档历史周报按其当时的审核路线判定，不因后来人员配置变化消失；未结束的旧路线继续其原审核流程，退回重提后使用新路线。
- 个人主页按工作方向与项目、设备采购与报销、贡献与绩效展示。已审核周报同时出现在绩效依据中，不自动生成分数、工资或付款。
- OA 大模型直接读取同一人员权限范围；工作成果仅来自已审核记录。未授权人员查询不会交给自由生成模型编造答案。管理员、经费负责人、既有两位技术审核人的可见范围保留，普通成员只能读本人工作台。

## 资料库入口补齐
